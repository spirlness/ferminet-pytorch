# FermiNet PyTorch 独立物理理论与计算正确性审查报告

审查日期：2026-09-21
审查基线：`97c7ca379e109268c57f345fc8cd48d8f4d5205a`
审查性质：**独立复核**。本次审查未参考 `audit_review/` 下任何既有报告或结论；所有判定均来自源码逐行核对、解析可解模型对照、对称性变换实验与端到端复评四类独立证据。
判定标准：物理理论正确性（哈密顿量、对称性、尖点条件、平衡分布、估计器无偏性）与计算正确性（自动微分、数值稳定性、参数梯度可达性、统计估计器行为）。

---

## 结论

本项目实现了一个**数值上正确、可收敛**的简化 FermiNet/VMC 原型。核心链路——库仑势计数与符号、对数波函数局域动能公式、同自旋 Slater 反对称性、MH 采样平衡分布、有限批次协方差梯度估计器、参考能量匹配——均通过独立验证。

端到端 H2（R=1.4 a.u.）120 epoch 训练在冻结参数后复评得到 **-1.17241 ± 0.00084 Ha**，参考值 -1.17447 Ha，误差 **+0.0021 Ha**（位于精确值之上，符合变分原理），R-hat = 1.0148。这是本代码库最有力的正确性证据。

但审查确认 **2 项高影响、4 项中影响、4 项低影响问题**。最严重的是统计与快速动能两条对外报告路径：`mcmc_stats` 在短链下系统性低估自相关时间（默认配置下约 5.5 倍），并在估计失败时**静默 fail-open**（曾观测到 39 倍高估有效样本数）——**该项已修复**，详见 §3.1；Hutchinson 单探针动能估计的误差达到信号本身的 1.5 倍以上，却作为默认快速路径暴露。此外，波函数的旋转不变性与核序置换不变性均不成立，Kato 尖点条件被距离软化破坏——这些需要在文档中如实声明。

## 三、详细发现与证据

### D1（高）`mcmc_stats` 系统性低估自相关时间，短链时静默失败 【已修复】

**证据。** 使用 ρ=0.95 的 AR(1) 链（解析真实 τ_int = 0.5·(1+ρ)/(1-ρ) = 19.5）检验 `estimate_mcmc_statistics`：

| 链长 T | 估计 τ_int | 相对偏差 | 估计 ESS 比值 | 真实 ESS 比值 |
|---|---|---|---|---|
| 4 | **0.500**（触底） | — | **1.000** | 0.0250 |
| 32 | 3.605 | −81.5% | 0.1387 | 0.0250 |
| 128 | 9.140 | −53.1% | 0.0547 | 0.0250 |
| 512 | 15.441 | −20.8% | 0.0324 | 0.0250 |

**两个独立问题叠加。**

1. **慢收敛偏差。** 即使 T=512 仍低估 21%。默认 `evaluation_steps=32` 落在 5.5 倍高估区间，报告的 SEM 因此偏小约 √5.5 ≈ 2.3 倍。

2. **静默 fail-open。** T=4 时 `_statistical_inefficiency` 的 Geyer 初始正序列（`range(1, rho.numel()-1, 2)`）在第 1 个 lag 就因 `pair <= 0` 截断，`paired_sums` 为空，函数返回 1.0。于是 τ_int 触底到 0.5、ESS = N，对一条真实效率 2.5% 的链报告 **100% 效率，高估 39 倍**。全程无任何警告。

**根因（修复期间定位）。** `_mean_autocorrelation` 与教科书直接计算逐位一致（FFT 实现无缺陷），问题出在**短链上扣除逐 walker 时间均值会引入约 1/T 的负自相关偏置**。实测：真值 ρ=0.95 的链在 T=4 时估出 ρ₁ = **−0.083**、ρ₂ = −0.413，故 Γ₁ = ρ₁+ρ₂ ≈ −0.50 ≤ 0。这意味着 fail-open 对短相关链是**系统性必然**触发，而非偶发噪声——恰恰在最需要保护时反转。该模块的设计目的正是避免"把相关样本当作独立样本"。

**修复。** `_statistical_inefficiency` 改为返回 `(g, status)`，状态取 `"ok"` / `"unresolved"` / `"insufficient_samples"`：

- Geyer 序列截断在首个配对 **且** 链长 < `MIN_TIME_FOR_AUTOCORRELATION`(=50) → `"unresolved"`，返回 `nan`；
- 时间步数不足以构成一个配对 → `"insufficient_samples"`，返回 `nan`；
- 链长充足时 Γ₁ ≤ 0 仍按 `g = 1` 处理（对长链这是**正确**结论，不能误标）。

`estimate_mcmc_statistics` 在非 `"ok"` 时把 `tau_int`、`statistical_inefficiency`、`ess`、`energy_sem` 全部置为 `nan`，新增 `autocorrelation_status` 字段，并发出 `UserWarning` 说明原因与补救方式。另外新增 `MIN_TIME_PER_TAU`(=20) 检查：链长少于 20 个自相关时间时发出欠解析警告，把残余的有限样本偏差也浮出水面。`train_vmc` 的上报逻辑相应区分两种情形，不再打印误导性的小误差棒。

**修复验证。**

| 场景 | 修复前 | 修复后 |
|---|---|---|
| AR(1) T=4, ρ=0.95（真值 τ=19.5） | τ=0.500, ESS=N, 无警告 | `status="unresolved"`, τ/ESS/SEM = nan, 1 条警告 |
| AR(1) T=32, ρ=0.95 | τ=3.61, 静默偏窄 | τ=3.01, `status="ok"`, 欠解析警告 |
| iid T=2048 | ESS≈N | `status="ok"`, ESS=N（未被误标） |
| 常数链 | ESS=N, SEM=0 | `status="constant"`, ESS=N, SEM=0 |
| AR(1) T=8192, ρ=0.9 | τ=9.35 | `status="ok"`, τ=9.43（真值 9.5） |

残余的有限样本偏差（Γ₁ > 0 但 τ 仍偏低，如 T=512/ρ=0.99 估 43.5 vs 真值 99.5）属于 Geyer 估计器的固有性质，无法"修复"，但现在由欠解析警告显式浮出，不再静默。

### D2（高）Hutchinson 单探针动能估计不可用于能量报告 【已修复】

**修复。** (1) `_compute_laplacian_hutchinson` 与 `compute_local_energy` 的复杂度表述已更正——探针数与体系规模无关，但探针循环是 Python 级、总成本随 N 增长，不是 O(1)；(2) `loss.py` 的 stats 字典新增 **solver provenance**（记录实际使用的 laplacian 方法与探针数）；(3) `compute_local_energy` 在请求 `hutchinson` 时发出 `UserWarning`；(4) `--evaluation_laplacian_method` 的 `choices` 中**移除 `hutchinson`**，使对外报告的能量在 CLI 层面就不可能来自随机估计器（`evaluate_trained_model` 另加显式 `ValueError` 守卫）。

**证据。** 固定构型上 `exact` 拉普拉斯给出 T = −1.0183。`hutchinson` 估计在 32 次重复间：

| 探针数 n | 重复均值 | 相对 exact 误差 | 重复间标准差 σ | σ·√n |
|---|---|---|---|---|
| 1 | −1.4292 | −0.4109 | 1.7579 | 1.758 |
| 2 | −0.7384 | +0.2799 | 1.1012 | 1.557 |
| 4 | −0.8083 | +0.2100 | 0.6312 | 1.262 |
| 8 | −1.0160 | +0.0023 | 0.5411 | 1.531 |
| 16 | −1.0780 | −0.0597 | 0.3937 | 1.575 |
| 32 | −1.0042 | +0.0141 | 0.2782 | 1.574 |

σ·√n 近似恒定 → **估计器无偏，方差 ∝ 1/n**，实现正确。问题在于量级：单探针的 σ ≈ 1.76，而信号本身仅 1.02——**误差是信号的 1.7 倍**。

更直观的批次层面证据：在另一组 64 walker、4 电子体系上，`exact` 批次均值 4.20，而 1 探针的批次均值给 **−126.8**（符号与量级均错），64 探针给 35.8（仍偏 8.5 倍）。原因是 ln\|Ψ\| 的 Hessian 迹在节点附近重尾，单次方向导数采样无法代表迹。

此外 `_compute_laplacian_hutchinson` 对 `num_samples` 使用 **Python 循环**，提高探针数的代价是线性 Python 开销，与源码注释宣称的"从 O(3N) 压缩至 O(1)"不符。

**建议。** 将 `hutchinson` 明确标注为"仅供训练期方差缩减，禁止用于能量/方差报告"；能量报告路径强制走 `exact`（当前 `evaluation_laplacian_method` 默认已是 `exact`，应保持并加断言）；若要保留快速路径，需实现论文所述的 Forward Laplacian 算子级传播，而非逐基方向 vmap。

### D3（中）最后一个相互作用层的双电子流网络恒为死参数 【已修复】

**修复。** `FermiInteractionLayer` 新增 `produce_two_electron_output` 开关（默认 `True`，保持该层的返回契约，故直接构造该层的既有测试不受影响）；`FermiNet` 装配时仅对**末层**传 `False`，不再创建其 `linear_two` / `res_proj_two`。回归测试改为断言**不存在任何零梯度可训练参数**。

**证据。** 以 `n_up=n_down=1`、`hidden_dim_one=16`、`hidden_dim_two=8` 构建模型，`loss.backward()` 后检查零梯度参数：

```
num_layers=1 → layers.0.linear_two.weight, layers.0.linear_two.bias, layers.0.res_proj_two.weight
num_layers=2 → layers.1.linear_two.weight, layers.1.linear_two.bias
num_layers=3 → layers.2.linear_two.weight, layers.2.linear_two.bias
```

**原因。** `FermiInteractionLayer` 同时更新 `h1` 与 `h2`，但只有 `h1` 流向轨道投影 `linear_orb_up/down`；`h2_next` 仅在下一层被消费。末层的 `h2` 输出无人使用，其更新网络（`linear_two` 与 `res_proj_two`）因而不在任何计算图上。

**说明。** 该结构继承自参考架构（官方 FermiNet 的末层双电子流输出同样不被消费），因此不是实现错误。但项目文档将 `FermiInteractionLayer` 描述为完整的自旋等变相互作用层，未说明末层约 1/3 的该层参数不参与训练。以默认 `num_layers=2` 计，`hidden_dim_two=16` 时约 16×16+16 = 272 个参数为空转。

**建议。** 在文档中注明；或在末层将 `linear_two` 置为 `None` 以节省参数与显存。

### D4（中）波函数不具备旋转不变性

**证据。** 将核坐标与电子坐标**同时**施加变换后比较 log\|Ψ\|（模型参数逐项拷贝）：

| 变换 | Δlog\|Ψ\| 最大值 |
|---|---|
| 平移 | 4.4e-15 ✓ |
| 绕 z 轴旋转 90° | **2.324** ✗ |
| 核序置换 | **3.341** ✗ |

**原因。** `features.py` 的 `ElectronFeatureEmbedding` 同时输入笛卡尔位移向量 r_{iI}（(B,N,M,3)）与 r_{ij}（(B,N,N,3)），二者直接进入普通 `nn.Linear`，网络无任何 SO(3) 等变约束。

**修复。** 新增 `rotation_invariant` 开关并**默认开启**：特征只由标量不变量构成——电子-核距离 d_{iI}、电子-电子距离 d_{ij} 与核电荷 Z_I（单电子流每核 2 维，双电子流 1 维）。由于整个前向通路（特征、包络、backflow、行列式）都不再含笛卡尔向量，波函数对整体旋转**逐位相同**。

**验证。**

| 变换 | 修复前 Δlog\|Ψ\| | 修复后 |
|---|---|---|
| 平移 | 4.4e-15 | 2.5e-14 |
| 绕 z 轴旋转 90° | **2.324** | **0.000（精确为零）** |

**表达力评估（这是选择该方案而非 E(3) 等变改写的关键依据）。** 对本仓库的体系（H2、LiH、H100 链）全部是**线性分子**，到各原子核的距离已完整确定电子在分子标架下的位置（轴向坐标 + 垂直距离），因此标量距离集**不损失表达力**。实测收敛对照（同 seed、400 epoch、512 walkers）：

| 特征模式 | H2 能量 | 误差 |
|---|---|---|
| `rotation_invariant=True`（新默认） | −1.17397 ± 0.00026 | +0.00050 |
| `rotation_invariant=False`（旧行为） | −1.17416 ± 0.00035 | +0.00031 |

差异 0.0002 Ha，落在 SEM 之内——**零代价获得严格旋转不变性**。

**说明。** 平移不变性成立且精确；同自旋置换反对称由行列式结构保证。`rotation_invariant=False` 保留旧的笛卡尔特征行为用于复现历史结果与消融对照，该模式**不具备**旋转不变性，文档已明确标注不得据此作任何"等变"声明（并有回归测试锁定）。

### D5（中）核序置换不变性缺失 【部分修复；原结论已更正】

**证据。** 交换 H2 的两个质子（`nuclear_coords` 与 `nuclear_charges` 同时翻转，其余可训练参数逐项拷贝），log\|Ψ\| 改变 3.341。

**原因（两级，原报告只识别出第一级）。**
1. `NuclearEnvelope` 的 `weights[k,j,m]` 与 `decay_rates_raw[k,j,m]` 按**核索引**参数化，核顺序改变即改变包络。
2. `ElectronFeatureEmbedding` 把 `[r_{iI}, d_{iI}, Z_I]` 按**核顺序**拼接为 `(B, N, 5M)` 后送入普通密集层；密集层对核块并不对称，因此即使包络完全不变，交换同核仍改变网络输出。

**已修复的部分（第一级）。** `NuclearEnvelope` 现按**电荷等价类**共享 `weights` 与 `decay_rates_raw`，组索引以 `persistent=False` 的 buffer 保存（随 `.to()` 迁移、不进 `state_dict`）。数学上两者**必须同时共享**：只共享其一时，对置换哑指标重标号即可看出 `sum_m π_{kjm} exp(-α_{kjm} d_im)` 仍会改变。不传电荷时 `G = M`，行为逐位不变。组按**首次出现顺序**编号而非电荷数值升序——后者会把异核体系（如 LiH 的 `[Z=3, Z=1]`）的核块重排，破坏向后兼容。

**未修复的部分，以及一个被实验否决的方案（本次更正的核心）。**

原报告建议「对同核体系施加参数共享」即可。实测表明这只解决第一级。为补上第二级，本次尝试了「按（电荷组，距离）对核轴做稳定排序后再拼接」——**该方案在纸面上成立，实测是错误的**：

- 排序在电子穿越两同核的**垂直平分面**时翻转核块顺序，而两个块在该面上**并不相等**（`r_{iI}` 方向不同），因此波函数在该余维 1 曲面上出现**不连续跳变**。
- 实测：电子沿两核连线穿越面时位置仅变 `2e-6` Bohr，log\|Ψ\| 跳变 **0.044**；而位置变化 4500 倍（`9e-3` Bohr）时才变 0.013。
- 后果：`∇²ln|Ψ|` 在不连续处失去意义，局域动能被污染。受控对照（同一 seed、400 epoch、512 walkers）显示 H2 能量由基线的 **−1.17405 Ha** 退化为 **−1.16242 Ha**，且某个配置一度给出 **−1.18922 Ha**——**低于精确参考值 −1.17447，违反变分原理**。
- 根本原因：**「有序拼接 + 排序」在数学上无法同时做到不变与连续**。距离并列时载荷不同，排序必然跳变。

该方案已从代码中移除。正确做法是放弃「有序拼接」，改为对核做**对称聚合**（例如把每个核的块过同一网络后求和/求均值），那是一次架构改写，不属于本轮范围。

**当前状态。** 包络部分在同核置换下严格不变（有正反两例回归测试）；**完整波函数仍不具备核置换不变性**，且这一限制现已在 `features.py` docstring、README 与 BEGINNER_GUIDE 中如实声明，并附上方案被否决的原因。连续性已由 `test_wavefunction_is_continuous_across_nuclear_bisector` 锁定，防止将来重新引入排序。

**教训。** 这是一个**设计级**缺陷——它不在任何一行代码里，行级审查看不到；只有跨对称变换的受控数值对照（基线 vs 集成后、同一随机种子）才能暴露。设计评审阶段曾把该残留缺陷判断为「测度零、可接受」，这个判断是错误的：垂直平分面是余维 1 曲面，MCMC 会反复穿越。

### D6（中）Kato 尖点条件被距离软化破坏 【已修复】

**修复。** 势能、几何特征与包络三处的距离核统一由 `sqrt(r² + eps)` 改为 **`sqrt(clamp(r², min=eps))`**。clamp 在**所有** `r² ≥ eps` 处是恒等变换，距离与未软化时**逐位相同**、偏置精确为零；而加性 eps 处处存在相对偏差 `eps/(2r²)`。`eps` 语义明确为「最小**平方**距离」，默认 `1e-24`（软化半径 `1e-12` Bohr，此前模型侧 1e-4 / 势能侧 1e-5 两个互不一致的值已统一）。

**验证。** r=1e-6 Bohr 处 `V_en` 由 −99,503.7 Ha 恢复为**精确的 −1e6 Ha**；α=1 包络在 r=1e-6 处的径向对数斜率由 −0.010 恢复为 **−α**（误差 < 1e-6）。新增重合点有限性与逐位精确性回归测试。

**如实保留的声明。** 软化核只保证**势能**在非重合点精确；波函数 ansatz 本身并不强制 Kato 条件——包络只有在学到的衰减率 α 恰等于 Z 时才给出正确的 −Z 斜率。文档已按此表述。

**证据。** 取 α=1 的各向同性包络 f(r)=exp(−α·sqrt(r²+eps))，测量核附近的对数径向斜率：

| r (Bohr) | d(ln f)/dr | Kato 要求 |
|---|---|---|
| 1e-3 | −0.995 | −Z = −1.0 |
| 1e-4 | −0.707 | −1.0 |
| 1e-5 | −0.0995 | −1.0 |
| 1e-6 | −0.010 | −1.0 |

软化尺度为 `sqrt(eps)`：`features.py`、`envelope.py` 用 eps=1e-8（尺度 1e-4），`hamiltonian.py` 用 eps=1e-10（尺度 1e-5）。斜率在 r → 0 时趋于 0，而 Kato 条件要求球平均波函数在核处具有非零径向导数 −Z。

势能侧同样受影响：r=1e-6 Bohr 处 `V_en` 实现值为 −99,503.7 Ha，真实库仑值为 −1,000,000 Ha（差 9.0e5 Ha）；核上势能被限制在 −100,000 Ha。

**影响评估。** 尖点是变分驻定条件，其能量影响是二阶的，实际数值偏差很小（H2 训练误差 +0.0021 Ha 即为例证）。但任何"精确 cusp"声明、或把核尖点标线图当作 cusp 验证的做法都不成立。

**建议。** 将 eps 明确解释为"数值软化尺度"并量化其能量偏差；如需 cusp 测试，应使用不改变非重合点哈密顿量的稳定计算，并以球平均径向对数导数做独立检验。

### D7（低）行列式权重归零后成为永久死分支

**证据。** 令 `det_weights[1] = 0` 后反向传播，梯度为：

```
[1.454651514131764, 0.0, -1.4546515141317637]
```

零权重的第 1 项梯度**精确为 0**。

**原因。** `_raw_forward_log_psi` 用 `sign(w)` 与 `log|w|` 组合构造多行列式线性组合。当 `w=0` 时 `sign(0)=0`，且 `log|0|` 被守卫为 −inf，该项被 `is_finite` 掩码移出求和，梯度路径完全断裂。该分支一旦跨过零点即无法恢复。

**建议。** 若需保证可恢复性，可对权重使用不经过零点的参数化（如 `w = softplus(raw)` 配符号参数），或对零权重加极小下界。

### D8（低）`clip_local_energy(method='none')` 静默替换 NaN

**证据。** 输入 `[-1.1, nan, -1.15]`，`clip_factor=5.0`，`method='none'`：

```
输出 = [-1.1, -1.15, -1.15]
```

NaN 被静默替换为中位数。

**缓解。** 训练主路径有保护：`vmc_surrogate_loss` 在 `clip_method='none'` 且存在非有限值时抛 `FloatingPointError`。但 `clip_local_energy` 是 `__init__.py` 的公开导出，直接调用时会掩盖数据问题。

**建议。** 在 `method='none'` 分支同样抛出或至少告警，而不是静默 `nan_to_num`。

### D9（低）JVP 求解器静默吞掉所有异常

**证据。** `_compute_laplacian_jvp` 使用 `except Exception` 捕获全部异常并回退到 `_compute_laplacian_exact`。

**影响。** 回退结果在数值上是正确的（`exact` 已验证），因此不产生错误答案；但会掩盖真实故障（`torch.func` 不可用、模型不兼容 `vmap`、形状不匹配），且 `warnings.warn` 在批量训练日志中极易被淹没，用户会误以为正在使用快速路径。

**建议。** 收窄捕获范围，或将回退事件计入返回的统计字典，使其可见。

### D10（低）模型几何缓冲与 `MolecularSystem` 可能静默失配

**证据。** `FermiNet.__init__` 通过 `register_buffer` 把 `nuclear_coords`、`nuclear_charges` 拷贝为自己的缓冲；`MolecularSystem.update_geometry()` 只更新体系对象自身。二者之间没有任何同步或一致性校验。

**影响。** 在模型构造之后调用 `system.update_geometry(...)`，将导致波函数使用旧几何、哈密顿量使用新几何，且不报错。

**建议。** 在训练入口校验模型缓冲与体系几何一致，或在 `update_geometry` 中同时更新关联模型。

### D11（提示）复杂度表述与实现不符

`_compute_laplacian_jvp` 构造 3N×3N 单位阵，对全部 3N 个基方向做 `vmap` 的 JVP——这是"批量化的逐基方向精确 Hessian 对角计算"，消除了 Python 循环，但**仍计算全部对角方向**，不同于论文所述的 Forward Laplacian 在网络前向中传播拉普拉斯，也不具备 O(1) 复杂度。`_compute_laplacian_hutchinson` 注释中"从 O(3N) 压缩至 O(1)"仅对固定探针数下的单步反向次数成立，且探针循环本身是 Python 级。

**建议。** 改称"批量化的逐基方向精确 Hessian 对角计算"，并给出时间与峰值显存随 N 的实测缩放。
